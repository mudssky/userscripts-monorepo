# 豆包模式排序设置

## Goal

豆包 chat 页面已从旧的「快速 / 思考 / 专家」模式更新为「快速 / 专家 / 办公任务」模式。`userscripts/ai-assistant-enhancer` 需要提供可排序的模式偏好设置，让用户能自定义自动切换优先级；默认仍优先「专家」，但用户可以把「快速」或「办公任务」调到更高优先级。

用户价值：脚本不再把模式策略固定写死为“专家优先、思考兜底”，而是尊重用户偏好，并能跟上豆包官方模式文案变化。

## Confirmed Facts

- 目标脚本位于 `userscripts/ai-assistant-enhancer`。
- 目标站点为 `https://www.doubao.com/chat`，现有 adapter 只匹配 `www.doubao.com/chat`。
- 当前代码里的模式类型为 `fast | thinking | expert | unknown`，中文文案为「快速 / 思考 / 专家」。
- 当前自动策略固定为：已在「专家」或「思考」则不处理；否则先尝试「专家」，失败后回退「思考」。
- 当前配置里只有 `preferredModeStrategy: 'expert-first'`，没有用户可编辑的模式顺序。
- 当前设置面板已有总开关、豆包开关、自动检查延迟、专家确认延迟、最近状态和立即检查按钮。
- 当前测试已覆盖配置归一化、控制器传参、设置面板交互和豆包 DOM 模式切换。
- 旧任务 `06-12-ai-assistant-experience-userscript` 的页面探测记录显示：2026-06-12 未登录豆包菜单为「快速 / 思考 / 专家」，未登录「专家」会弹登录，「思考」可用；该记录可能已因豆包更新而过时。

## Requirements

- 更新豆包模式模型，支持「快速 / 专家 / 办公任务」三种用户可排序模式。
- 默认模式顺序为「专家 / 办公任务 / 快速」，避免专家不可用时仍落回最低质量的快速。
- 用户可在右侧设置面板中调整豆包模式顺序。
- 排序设置需要持久化到 GM storage，刷新页面后保持用户设置。
- 自动切换策略改为按用户配置顺序依次尝试模式：
  - 若当前模式已是顺序中最高优先级的可接受模式，则不重复切换。
  - 若当前模式不是目标优先模式，则按顺序尝试选择第一个可用模式。
  - 如果高优先级模式因登录、权益、菜单项缺失或切换未生效失败，应继续尝试下一项。
  - 所有候选都失败时，状态面板应显示可排查的失败原因。
- 兼容旧配置：已有 `preferredModeStrategy: 'expert-first'` 或缺少新字段的配置应自动迁移/归一化为默认顺序。
- 更新状态文案，不再写死「回退思考」；应能表达“已切到专家 / 已切到办公任务 / 当前已是快速 / 某模式不可用后已尝试下一项”等结果。
- 更新「专家确认延迟」相关 UI 文案，使其适用于任意模式切换确认，而不是只描述专家。
- 新排序组件应适合 userscript 右侧窄面板：
  - 展示三种模式的当前顺序。
  - 支持通过按钮调整上移/下移，或使用等价的稳定排序交互。
  - 禁用态跟随总开关和豆包开关。
  - 不依赖拖拽作为唯一交互，避免在宿主页面与 Shadow DOM 内难以稳定操作。
- 不绕过登录限制，不自动登录，不处理账号权益。
- 不扩展到除豆包以外的 AI 助手。
- 实施前应重新探测当前豆包 DOM 或通过可复现测试 fixture 补充新模式文案证据；若真实页面仍存在「思考」或文案与预期不一致，应回到 PRD 更新需求。

## Acceptance Criteria

- [ ] `DEFAULT_CONFIG` 中豆包默认顺序以「专家」为第一优先级，并包含当前支持的三个豆包模式。
- [ ] 旧配置或异常配置经过 `normalizeConfig` 后能得到合法、去重、完整的模式顺序。
- [ ] 设置面板展开后能看到豆包模式顺序设置，并可通过键鼠可操作控件调整顺序。
- [ ] 调整模式顺序会调用 `onConfigChange` 并持久化到配置结构。
- [ ] 控制器调用 adapter 时会传入当前配置的模式顺序。
- [ ] adapter 会按配置顺序尝试模式，不再固定“专家失败回退思考”。
- [ ] 豆包模式识别、菜单查找和状态文案支持「办公任务」。
- [ ] 未登录或高优先级不可用时，脚本会尝试下一个配置模式，并把原因展示到最近状态。
- [ ] 相关配置、控制器、adapter 与设置面板行为有单元测试覆盖；不为纯 CSS 或静态布局写测试。
- [ ] `pnpm -C userscripts/ai-assistant-enhancer qa` 通过。

## Decisions

- 豆包「专家」不可用时，默认第二优先级使用「办公任务」，完整默认顺序为「专家 / 办公任务 / 快速」。
